FruitHub: Local Setup & Complete Test Guide

Plain-language steps for running the app, checking animations, testing owner/customer orders, and understanding UPI payment verification.

Documentation home · Security · Payment safety · Owner handbook

Important: Do not run database migrations against a production or important database without confirming the target and taking a backup. The current checkout uses direct UPI and manual owner verification; it does not automatically confirm real transfers or process refunds.

1. What you will test

  • Backend API and storefront running locally.
  • Owner UPI settings, products, stock, and animated product preview.
  • Customer location and delivery-area acknowledgment.
  • Booking, UPI app handoff, transaction-reference submission, and owner verification.
  • Order status and customer receipt confirmation for customer-arranged delivery.

2. Start the backend

Open a new PowerShell terminal in VS Code and run:

Set-Location 'C:\Users\HP\OneDrive\Attachments\app\fruithub\backend'
..\..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

Keep this terminal open. A working API should respond at http://127.0.0.1:8000/api/v1/health. Interactive API documentation is at http://127.0.0.1:8000/docs.

If the command reports missing packages, install from the repository requirements file only if that environment is the one you intend to use:

Set-Location 'C:\Users\HP\OneDrive\Attachments\app'
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

3. Database check and migration

The current latest Alembic revision is 4f82b6a3c1d0. Its parent is d7b4c6a9e215. Check the actual database revision before upgrading.

  1. Confirm the database name/host configured for the backend by checking backend\.env locally. Do not paste or share the file because it contains credentials.
  2. In pgAdmin, connect to that exact database and use right-click database → Backup. Save a custom-format backup somewhere safe. Do not back up the test database in place of your real intended database, or vice versa.
  3. Run the read-only revision checks:
Set-Location 'C:\Users\HP\OneDrive\Attachments\app\fruithub\backend'
..\..\.venv\Scripts\python.exe -m alembic current
..\..\.venv\Scripts\python.exe -m alembic heads

Expected head: 4f82b6a3c1d0. If the current revision is d7b4c6a9e215, and you have confirmed the target database and backup, apply the migration:

..\..\.venv\Scripts\python.exe -m alembic upgrade head

Then verify with ..\..\.venv\Scripts\python.exe -m alembic current. If the current revision is unknown, behind the expected parent, or the database target is unclear, stop and ask for help rather than upgrading.

pgAdmin: use it to confirm the database and make/restore backups. Do not manually create the UPI column or alter the payment enum; Alembic handles those schema changes.

4. Start the frontend

  1. In VS Code, open frontend\index.html.
  2. Use the VS Code Live Server extension’s Open with Live Server action. If asked, use port 5500.
  3. Open the URL Live Server displays. It should end in /frontend/index.html.

The frontend API configuration currently points to http://127.0.0.1:8000/api/v1. The backend CORS configuration must allow the exact Live Server origin, usually http://127.0.0.1:5500 or http://localhost:5500.

5. Prepare owner, store, and products

  1. Log in using an owner account whose store is active and admin-approved. Use the existing account details for your own local/test setup; this guide does not assume or provide passwords.
  2. Open frontend/pages/owner.html (Owner panel in the site navigation) and save the owner’s correct UPI ID, also called a VPA. Do not enter a UPI ID unless the owner controls it.
  3. Create or verify at least one available product. Check its name, category, price, quantity/unit, image, and stock.
  4. For animation testing, open the product detail page while logged in as the owner. Upload a clear product photo or regenerate the preview. Wait for processing to finish, refresh, and confirm the preview appears.
If checkout reports that the store has not configured UPI, the owner UPI ID was not saved for the store that owns the cart’s product. Confirm you logged in to the right owner and that the store is approved and active.

6. How the animation appears

  • Home page: Three.js shows FruitHub’s built-in decorative product-type models.
  • Product page: the owner-generated preview is based on the uploaded photo and depth map. Drag to tilt the depth effect; zoom with scroll/pinch or viewer buttons.
  • Cart/booking page: the product’s generated animated WebP is shown when available; without one, the cart shows the still product image.

The owner can upload/replace the photo, regenerate the preview, or remove the preview on the product detail page. Removing it makes the cart use the normal photo. The product page’s interactive view is a moving depth effect from a photo, not a fully modelled 3D object. The animation is only a visual preview; it does not alter booking, stock, delivery, or payment.

For a readable end-to-end animation check: add one product with a generated preview and one product without a preview to the cart. Confirm the first animates, the second shows its still photo, and opening the product name takes you to the detail page.

7. Customer booking and location test

  1. Log out of the owner account and log in with a customer account. Customer accounts must have phone verification completed to check out.
  2. Open Fruits, Juices, or Dry fruits; choose an available product and add it to the cart.
  3. Select a saved complete address. The app checks its distance from the store and tells you whether seller delivery is available.
  4. For an address outside the store delivery area, tick the acknowledgment that you will arrange and pay for delivery separately. FruitHub charges no external delivery fee.
  5. Check the total before placing the order: product total, discounts, and any seller delivery fee are shown. An outside delivery charge is not included.
  6. If creating a test address, enter valid latitude and longitude. Do not use a fabricated address for a real order.

8. UPI payment and owner verification

  1. Place the order. The checkout displays the payee/store, UPI ID, amount, and an upi://pay link.
  2. On a phone, tap Open a UPI app. Your device may offer PhonePe, Google Pay, Paytm, or another installed app that supports the standard UPI link. The exact app chooser depends on the phone and installed apps.
  3. If no app opens, copy the UPI ID and payee/amount, then open the UPI app yourself and pay manually. Verify the payee and amount in the app before authorizing.
  4. Return to FruitHub → My orders. A pending order can reopen its payment link. Submit the transaction reference/UTR from your UPI app.
  5. Submitting a reference is only a claim. The order remains unpaid. The owner must compare the payment in their own UPI/bank account and then choose Confirm money received in the Owner panel.
  6. If the owner rejects a reference, the order is cancelled and stock restored. If a reference remains unverified, its stock reservation expires after 24 hours.
The app does not receive a payment confirmation from PhonePe, Google Pay, or Paytm. Never mark a real order paid based only on a screenshot or customer-entered reference. Direct UPI refunds are also handled by the owner outside FruitHub.

A real UPI transfer sends real money. For a first test, prefer a test VPA/account or coordinate with the owner and use a small amount they both agree to. Do not submit a fake reference to a real store.

9. Owner order and delivery checks

  • Owner sees only their own store’s submitted payment references.
  • Owner verifies the amount/reference in their account before confirming.
  • Confirmed payment changes the order to paid/placed and makes it available in the owner order flow.
  • Owner advances the order through allowed status steps, one at a time.
  • For an outside-area order, owner cannot mark seller delivery as dispatched.
  • Customer arranges outside delivery separately and confirms receipt after the order is ready.
  • Canceling a paid direct-UPI order does not automatically refund the customer; the owner handles that outside FruitHub.

10. Automated checks

The backend test fixture sets its own database target to port 5433 and database fruithub_test, then drops/recreates test tables and truncates test data. Ensure that test database exists and is disposable before running tests.

Because the virtual environment is at the parent app directory, run:

Set-Location 'C:\Users\HP\OneDrive\Attachments\app\fruithub'
& 'C:\Users\HP\OneDrive\Attachments\app\.venv\Scripts\python.exe' -m pytest backend\tests -q

Expected from the last run: 84 passed. A changed test count or failure should be investigated; do not treat the old result as proof that your current environment passed.

Frontend syntax checks (run in PowerShell):

node --check 'C:\Users\HP\OneDrive\Attachments\app\fruithub\frontend\js\pages\cart.js'
node --check 'C:\Users\HP\OneDrive\Attachments\app\fruithub\frontend\js\pages\orders.js'

11. What has not been verified

  • The Alembic migration has only been checked/rendered offline; it has not been applied to your database.
  • No real PhonePe, Google Pay, or Paytm transfer has been made or automatically verified.
  • The UPI app chooser must be tested on a phone with UPI apps installed; a desktop browser cannot prove that handoff.
  • SMS verification in development prints the OTP in the backend terminal; a production SMS provider has not been configured here.
  • The local backend/API and frontend must both be running for a complete browser test.
